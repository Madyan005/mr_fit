# MR-Fit mobile (Flutter, Android)

Verified with Flutter 3.50.1 / Dart 3.14.0 (see `docs/PROGRESS.md`).

## Setup (once)

The Android scaffold (`android/`, generated by `flutter create`) is committed, with
`minSdk = 26` already set. On a fresh clone:

```bash
cd mobile
flutter pub get
dart run build_runner build      # drift code generation (*.g.dart is not committed)
```

(`--delete-conflicting-outputs` is gone in build_runner 2.17 and is ignored if passed.)

## Run

```bash
flutter run                    # Mock mode is the default: runs on an emulator, no BLE/camera needed
flutter test                   # unit, golden, data-layer and widget tests (fake backend, no network)
```

**Session** tab: the 7-phase velocity-tracked session (connect, exercise/goal, positioning,
3-tap calibration, live HUD, set end, rest and coaching). In Mock mode it plays three demo
sets: clean squat, fatigue bench press, valgus squat. **Settings → Data source** switches
Mock/Real (Real needs the hardware REAL SLOTs, not implemented yet).

The backend URL is entered on the sign-in screen (default `http://10.0.2.2:8000`, the
emulator's alias for the PC). From a phone use `http://<PC-LAN-IP>:8000`.

Opt-in end-to-end test against a running throwaway API (it creates a new account each run;
start the server with `LLM_BACKEND=fake GEMINI_ENABLED=false AI_COOLDOWN_SECONDS=0`):

```bash
MRFIT_LIVE_API=http://127.0.0.1:8000 flutter test test/e2e/live_backend_test.dart
```

Local data: sets are written to an encrypted SQLCipher database first (key in the Android
Keystore via `flutter_secure_storage`) and uploaded by a retry queue; see
`docs/DECISIONS.md` D-064…D-066.

## Architecture

```
lib/
  app/bindings.dart        THE one place that binds Mock vs Real (sensor, vision, time sync)
  app/providers.dart       data-layer wiring (API, encrypted DB, sync queue); app/session.dart sign-in state
  domain/                  pure Dart: interfaces, models, contract, MetricsEngine (no Flutter, no hardware)
  data/sensors/mock|real   MockSensorSource / REAL SLOT
  data/vision/mock|real    MockVisionPipeline / REAL SLOT
  data/timesync/           MockTimeSync, TapTimeSync
  data/api|auth|storage    dio client with single-flight token refresh, typed endpoints, secure storage
  data/local|sync          drift + SQLCipher DB, SetRepository, SyncService (retry queue)
  features/food/           optional, isolated
  app/session/             SessionController (7 phases), session providers
  data/feedback/           vibration + TTS cues, foreground service
  presentation/            screens (Riverpod): auth, track, library (+heatmap), stats, coach, session, settings
```

Rule: hardware names (ESP32, packet structs, UUIDs, MACs) may appear **only** in
`data/sensors/real/` and `data/vision/real/` files marked `// REAL SLOT`.
